# ADR-0001：修复竞态后冻结 v2.5、搁置 v2.6 与单锁重构，直奔 v3.0

- **状态**：已采纳
- **日期**：2026-11-24
- **关联文档**：`docs/v2.4_pivot_analysis.md`、`docs/v2.5.md`、`docs/archive/ThreadPoolV26.h`

## 背景

在完成 `v2.4`（单锁单任务基线）与 `v2.5`（单锁两端批量化，8 线程 262,144 任务中位数由 ~245 ms 压降至 ~11.2 ms）后，`/deepen` 普查识别出单锁变体演进中的多项重构候选（`C2` 单锁内部队列接缝、`C3` `Batch` 深化、`C4` 遥测快照、`C6` 压测编排重构）及未完成的 `ThreadPoolV26.h`（容器粒度升级至 `std::deque<std::vector<TaskType>>`）。本项目存在明确封板截止时间（2027-01-10），核心交付目标为 `v3.0` 工作窃取（Work-Stealing）+ 缓存行对齐（`alignas(64)`）+ 轻量 DAG 依赖调度 + Linux `perf` 硬件计数器定量剖析。

## 决策

1. **冻结双单锁基线**：保持 `ThreadPool.h`（`v2.4`）只读冻结；在人类开发者亲手修复 `ThreadPoolV25.h:297`（全局锁外读取 `workers_.size()` 与 `shutdown()` 的并发读写竞争）并通过 TSan 验证后，冻结 `ThreadPoolV25.h` 作为“单锁批量化基线”。
2. **搁置并归档 `v2.6`**：将未完成的 `ThreadPoolV26.h` 移至 `docs/archive/ThreadPoolV26.h` 归档保存，不再补全其中的 TODO 3–7。
3. **停止单锁重构（止损 `C2`、`C3`、`C4`、`C6`）**：不再抽象单锁共用基类或重写 `v2.5` 遥测/批量接口，避免在过渡性单锁架构上产生沉没成本。
4. **延后可视化脚本（`C7`）**：`plot_benchmark.py` 暂不维护，待 `v3.0` 压测数据稳定后一次性重写。

## 理由

- 单锁拓扑的物理上限（全局锁串行搬移与跨核缓存行争用）已在 `docs/v2.5.md` 中定量测得并验证，`v2.6` 仅能在单锁框架内压缩常数项，无法解决多生产者自产自销、DAG 嵌套提交与粗/变长任务均衡问题。
- 在 2027-01-10 硬死线约束下，工程预算应集中投入 `C1 + C5`（跨平台 `CMakeLists.txt` 构建与 TSan/ASan 验证底座）及 `v3.0` 架构跃迁。

## 后果与约束

- 后续审查与迭代**不再重复建议**对 `v2.4`/`v2.5` 做单锁骨架抽取（`C2`）、`Batch` 重构（`C3`）、遥测重写（`C4`）、压测流水线重构（`C6`）或 `v2.6` 续写。
- 新版本 `v3.0` 直接挂接在 `SchedulerContract.h` 的调度器契约接缝上，与冻结的 `v2.4` / `v2.5` 进行同进程 A/B 对照。
